Yes. I found a few, and one looks substantially more mature than the typical ChatGPT-specific extensions.

### Best one to try first: **Copy as Markdown by yorkxin**

It has about **40,000 Chrome users**, is Featured in the Chrome Web Store, was updated **June 2, 2026**, and the GitHub project has **759 commits / ~758 stars**. It supports **selected text → Markdown**, including formatted text, and is designed for arbitrary webpages rather than ChatGPT specifically. :chatgpt-content-reference{index="0"}

[Chrome Web Store — Copy as Markdown](https://chromewebstore.google.com/detail/copy-as-markdown/fkeaekngjflipcockcnpobkpbbfbhmdn?utm_source=chatgpt.com)  
[GitHub — yorkxin/copy-as-markdown](https://github.com/yorkxin/copy-as-markdown?utm_source=chatgpt.com)

That **generic-page approach is probably what you want**. It doesn't need to know that something is `.assistant-message > .markdown > ...`; it operates on the selected DOM content. So ChatGPT rearranging its outer component structure should matter much less.

### Another interesting one: **notlmn/copy-as-markdown**

This one has around **10,000 Chrome users** and specifically supports selected HTML, GFM tables, fenced code blocks and even **MathML → LaTeX** conversion. :chatgpt-content-reference{index="3"}

[GitHub — notlmn/copy-as-markdown](https://github.com/notlmn/copy-as-markdown?utm_source=chatgpt.com)

For ChatGPT output containing equations, this is particularly interesting.

### The architecture I think you'll find most interesting

I also found a very small project called **LLM Copy as Markdown**. It has basically no adoption yet—only 2 commits and 0 stars—so I wouldn't choose it because of maintenance. But its implementation is almost exactly how I'd solve your CSS-selector problem. :chatgpt-content-reference{index="5"}

Instead of finding the ChatGPT response with selectors, it intercepts the browser's `copy` event and does roughly:

```text
window.getSelection()
    ↓
selection.getRangeAt(0)
    ↓
DOM Range
    ↓
walk only nodes intersecting that Range
    ↓
<strong> → ** **
<em>     → * *
<a>      → [text](url)
<pre>    → ```
<ul>     → -
<table>  → Markdown table
```

The author explicitly says the core converter uses semantic HTML tags such as `<strong>`, `<em>`, `<code>`, `<pre>`, `<ul>`, `<ol>`, headings, blockquotes and tables. The only site-specific configuration is mostly things such as **math nodes and code-language extraction**. :chatgpt-content-reference{index="6"}

[GitHub — LLM-COPY-AS-MARKDOWN](https://github.com/S0uth3rnSp4rk/LLM-COPY-AS-MARKDOWN?utm_source=chatgpt.com)

That is much closer to a durable solution than:

```js
document.querySelector(
  '[data-message-author-role="assistant"] .markdown.prose...'
)
```

### One more worth watching

**Page Content to Markdown** is unusually active for this niche: its repository currently shows **95 commits** and has dedicated ChatGPT/Claude/Grok extractors, while also offering **right-click → Copy selection as Markdown**. :chatgpt-content-reference{index="8"}

The dedicated extractors can still break when ChatGPT changes internals, but the selected-text feature is less dependent on them.

[GitHub — page-content-to-markdown](https://github.com/jaredatch/page-content-to-markdown?utm_source=chatgpt.com)

### For your extension

I suspect the fundamental fix is **stop finding the ChatGPT message at all**.

If the user highlights something, you already have the strongest possible locator:

```js
const selection = window.getSelection();
const range = selection.getRangeAt(0);
const fragment = range.cloneContents();
```

Then convert that fragment to Markdown.

You only need ChatGPT-specific handling for oddities such as citations, KaTeX/math, interactive code blocks, generated UI widgets, and perhaps partially selected tables. Everything else can be semantic-DOM based.

So I'd first try **yorkxin's Copy as Markdown** and see if it already replaces your extension. If you're developing yours because you need better ChatGPT-specific handling, I'd actually combine **yorkxin/notlmn's generic strategy** with the **Range-based approach from LLM-COPY-AS-MARKDOWN**, rather than continuing the CSS-selector whack-a-mole.
